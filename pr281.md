Closes [#281](https://github.com/iCog-Labs-Dev/cordial-f1r3node/issues/281).

## Summary

This PR extends the Lean specification with the evidence, authentication, and
authorization concepts needed to state Cordial tiered-slashing safety
precisely. It keeps raw claims, structural equivocation validity,
cryptographic authentication, and protocol authorization as separate layers.

The model reuses the existing Lean `Equivocation` and `Equivocator`
predicates. It does not treat arbitrary proof bytes as authenticated evidence
and introduces no cryptographic axioms.

## What changed

- Add `LeanVerification/Slashing.lean` and export it from the root
  `LeanVerification` library.
- Define `RawEquivocationEvidence` with:
  - the claimed offender;
  - two conflicting block identities;
  - the original Cordial offense round;
  - opaque proof material.
- Define `ValidEquivocationEvidence`, requiring:
  - two present and distinct blocks;
  - the same creator for both blocks;
  - equality between that creator and the claimed offender;
  - mutual non-observation;
  - equal computed Cordial depth;
  - binding between that depth and the claimed offense round;
  - the existing `Equivocation` predicate.
- Define the explicit `CryptographicVerificationAssumption` boundary and
  `EvidenceAuthenticated` predicate for externally verified content identity
  and signatures.
- Define `PenaltyAuthorizationDecision`, `PenaltyAuthorizationPolicy`, and
  `AuthorizedPenaltyEvent` to bind verified evidence, offender, offense round,
  PoR application round, and the finalization or attestation decision that
  authorizes application.
- Keep Cordial depths and PoR application rounds as separate coordinate
  systems. The model does not assume a numeric ordering between them; instead,
  the authorization policy binds the exact application round.
- Add a detailed Lean-to-Rust contract mapping and document the remaining
  equal-depth conformance boundary.

## Theorems

- `validEvidence_implies_equivocation`
- `validEvidence_implies_equivocator`
- `validEvidence_offender_unique`
- `validEvidence_round_bound`
- `authorizedEvent_contains_validEvidence`
- `authorizedEvent_offender_bound`
- `authorizedEvent_applicationRound_bound`

Together, these prove that structurally valid evidence identifies the creator
of the conflicting blocks, yields the existing Cordial equivocator predicate,
binds both blocks to the claimed offense round, and prevents an authorized
penalty event from substituting a different offender, evidence record, or PoR
application round.

## Rust integration boundary

The latest `dev` implementation now includes:

- sealed `VerifiedEquivocationEvidence` values created only by
  `verify_equivocation_evidence`;
- explicit `EquivocationAuthorizationPolicy` and
  `CheckpointEquivocationAuthorizationPolicy` boundaries;
- private authorization capabilities carried by `EquivocationPenalty`;
- finalized Cordial and checkpoint-prefix authorization paths.

These changes match the formal separation between raw evidence,
authentication, and authorization. One conformance distinction remains:
Lean's existing `Equivocation` requires two blocks at equal depth, while the
Rust verifier accepts pairwise-incomparable blocks at different depths and
records their minimum depth as the evidence round. This PR preserves the
existing Lean definition, as required by #281, and documents the mismatch
explicitly rather than claiming full Rust conformance.
